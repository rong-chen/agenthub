# 修复多会话并发执行与独立状态隔离

## 问题原因

此前 `AppStateProvider` 中采用全局单一的 `_isBusy` 布尔变量与单会话数据流变量控制任务调度。
导致当某个会话正在运行改代码或问答任务时，系统把全部会话的输入层与发送操作全部加锁，用户切到其他会话时输入框被禁用，无法在其他会话中进行聊天或触发新任务。

## 修复方案

1. 忙碌状态按会话隔离
- 将全局的 `_isBusy` 升级为会话集合 `_busySessionIds`。
- `isSessionBusy(sessionId)` 仅判断特定会话是否处于忙碌状态。
- 当前活跃会话若不在执行中，输入框与发送按钮完全处于就绪可用状态。

2. 取消与数据流独立控制
- `_abortedSessionIds` 与 `_sessionStreamMsgIds` 均按会话 ID 隔离。
- 中止任务时只定向终止目标会话所绑定的 Claude 进程实例或请求流，绝不影响其他并行的会话。

3. 会话列表状态感知
- 在左侧会话列表中为正在运行中的会话标注“运行中”微章，便于直观感知后台各个会话的执行状态。
